Adding Ethernet to the IoT PLC

The current board has no free pins for the STM32H750's native Ethernet MAC. This page shows the four ways to add Ethernet, why a W5500 on the ESP32-S3 is the right step for the next board revision, and how dual-port Ethernet arrives with the embedded-Linux head in v2.

v1.1 W5500 SPI Ethernet on the ESP32-S3 v2 STM32MP135 Linux head, 2 × Ethernet Rejected for now native RMII on the LQFP100 H750 Date 2026-10-03
00Verdict
Recommendation

Put a WIZnet W5500 on the ESP32-S3's free SPI pins (IO9–IO14) with an RJ45 that has integrated magnetics. The STM32 side does not change at all, and the ESP32 gains a wired uplink next to Wi-Fi for Modbus TCP, MQTT and the web UI.

For a true industrial dual-port device (line topology, deterministic Modbus TCP, OPC UA), plan the v2 head around the STM32MP135, which has two Gigabit MACs on chip.

01Constraint

Why native Ethernet on the H750 doesn't fit this board

The STM32H750VBT6 has an Ethernet MAC, but in the 100-pin package the RMII signals can only use one fixed set of pins (Port G is missing). All nine are already used by I/O you need.

Freeing them would mean moving RS-232, the ESP32 link, the FRAM bus and two analog channels, which is a full re-pin of the CPU page. A bigger package (STM32H750ZBT6, LQFP144) removes the conflict but is also a redesign. The ESP32-S3 has no Ethernet MAC, so SPI Ethernet is the only option on that side.

Bill of materials (about US$3–6)

  • W5500 (LQFP-48, −40…+85 °C), 25 MHz crystal ±30 ppm with 2 × load caps, 12.4 kΩ 1% on EXRES1, decoupling 10 µF + 6 × 100 nF, ferrite bead to the analog 3.3 V pins.
  • RJ45 with integrated magnetics and LEDs (e.g. HanRun HR911105A for prototypes, a Würth or Pulse industrial jack rated −40…+85 °C for production), 1500 Vrms isolation.
  • ESD/surge: low-capacitance array on the line side (e.g. RClamp0524P or TPD4E05U06), placed at the connector.
  • Bob Smith termination: 4 × 75 Ω to a common node, then 1 nF/2 kV to chassis. Shield to PE through 1 nF/2 kV ∥ 1 MΩ (same pattern as the RS-485 port).
  • Power: W5500 draws about 130 mA at 3.3 V at 100 Mb/s. TPS563201 (3 A) has margin; recheck the 3.3 V budget with Wi-Fi TX peaks.

Layout rules

  • Differential pairs TX±/RX± 100 Ω, under 25 mm from W5500 to jack, no vias, no stubs.
  • Void all copper (planes included) under the magnetics/jack isolation gap; keep at least 2 mm creepage between line side and logic ground.
  • Crystal within 10 mm of the W5500, guarded by ground; SPI under 50 mm.
04Firmware

IoTHandler changes

  • Use the ESP-IDF Ethernet driver (esp_eth_mac_new_w5500() / esp_eth_phy_new_w5500()) through the Arduino-ESP32 3.x ETH class (PlatformIO pioarduino platform), so lwIP runs both WIFI_STA and ETH netifs.
  • Interface priority: Ethernet first, Wi-Fi as fallback; reconnect the MQTT/AWS IoT client on interface change.
  • Add a Modbus TCP server (port 502) on the ESP32 that maps registers to the process image already shared over stm_link_v2, so SCADA/HMI panels can read the PLC directly.
  • New pins in config.h: PIN_ETH_SCLK 12, PIN_ETH_MOSI 11, PIN_ETH_MISO 13, PIN_ETH_CS 10, PIN_ETH_INT 9, PIN_ETH_RST 14.
  • Static IP / DHCP and Modbus unit ID become fields in the provisioning config (device_config.h).
05v2

Native dual-port Ethernet in v2

Industrial customers wire PLCs in a line (cabinet to cabinet) and expect two ports with an internal switch. That needs a real MAC with RMII/RGMII, which the v2 Linux head provides.

  • STM32MP135F: two GbE MACs → two RGMII PHYs (e.g. RTL8211F-VD-CG industrial or DP83867IR), or one MAC → 3-port switch (Microchip KSZ8863RLL or LAN9353) for a daisy-chain with one MAC.
  • Keep the W5500 footprint out; the ESP32 becomes an optional Wi-Fi/BLE co-processor.
  • Protocols that become possible: Modbus TCP with deterministic timing, OPC UA server (open62541), MQTT/Sparkplug B, EtherNet/IP adapter or PROFINET device via commercial stacks.
  • If you instead keep an MCU-only design, the alternative is STM32H750ZBT6 (LQFP144) + LAN8742A on RMII, with the I/O re-pinned to free PA1/PA2/PC1/PA7/PC4/PC5 and using Port G for TX.
