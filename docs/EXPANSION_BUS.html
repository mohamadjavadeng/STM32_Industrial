The bus behind the modules

Choosing the backplane protocol for a modular IIoT PLC: why an expansion bus must not be built like a field bus, why it should be a master-clocked SPI cycle rather than CAN or RS-485, and exactly how it lands in the process image this firmware already has.

01 Recommendation

An expansion bus is not a field bus

Every mistake available here comes from one confusion. A field bus connects devices you did not build, over wiring you do not control, at distances you cannot predict. It must be tolerant, addressable, multi-vendor and therefore slow. An expansion bus connects boards you designed, over a connector you designed, 20 mm apart. It must be fast, deterministic and cheap in CPU time. Building the second like the first is how a modular PLC ends up with a 10 ms I/O update and DIP switches on every card.

The recommendation

Use a master-clocked synchronous SPI backplane. The head CPU is the only master, each slot has its own chip select, and one transaction per slot per cycle exchanges outputs and inputs in the same clocks. Address the modules geographically — the slot tells the module who it is, through resistors on the backplane, so a replacement card needs no configuration. Carry rare traffic (identity, parameters, diagnostics) in a small mailbox window inside the same fixed-size frame, so there is exactly one frame shape, one DMA length per slot, and no bus arbitration anywhere in the system.

That cyclic/acyclic split is the same one PROFINET, EtherCAT and PROFIBUS-DP all make: a cyclic channel that is fast and never blocks, plus an acyclic mailbox that is slow and never urgent. It is worth copying because it is the single design decision that stops a diagnostic read from ever delaying an output update.

Keep
  • crc16() from modbus_crc.c — still the only CRC in the project.
  • Little-endian on the wire, everywhere, including the CRC.
  • The GW_Q_* quality codes — a missing module is just GW_Q_COMM_FAIL.
  • The GW_ST_* status codes, reused verbatim as mailbox result codes.
Change
  • Move the backplane master off SPI2: its only DMA stream collides with USART3 (§08).
  • Bump GW_REGION_COUNT to 9 and GW_PROTO_VERSION_MINOR — adding a region is additive, so minor.
Add
  • GW_REGION_EXP 0x08 — the rack's I/O, one sub-map per slot.
  • exp_master.[ch] on the head, exp_slave.[ch] on every module.
  • shared/exp_model.h, compiled by both, under the same one-copy rule as gw_model.h.
02 Candidates

Five options, measured on the same job

The job: an eight-slot rack, each module exchanging 16 bytes of inputs and 16 bytes of outputs, refreshed every PLC cycle. What matters is the time to refresh the whole rack once, and what that costs a CPU that also has to run the Modbus scanner and the ESP32 link.

The one case that flips this

If your expansion modules are not in the same rack — if they sit in another enclosure, connect by cable, or need to be metres away — then SPI is the wrong answer and CAN is the right one. SPI is single-ended and unterminated by nature: it survives a backplane connector and dies on a cable run. That is the only question in this document whose answer changes the protocol itself, which is why it is the first one asked in §12.

03 Topology

Three shared wires, one private wire per slot

Clock, MOSI and MISO run the length of the backplane and every module taps all three. Only the chip select is private, and that single private wire does all the work that a field bus needs an address field, an arbitration scheme and a collision-recovery timer to do. There is never more than one talker because the master physically enables one.

04 Addressing

The slot knows who it is, the module does not

Give every module four input pins — PC0..PC3 is a convenient free group on the VG — and tie them on the backplane, per slot, to ground or to 3V3. The module reads them once at boot and that is its address. Sixteen slots, no DIP switches, no address collisions, no commissioning step.

The payoff is the one that matters in the field: a technician swaps a failed analog card for a spare from the shelf, and it comes up as the right slot with the right parameters, because the rack holds the identity and the head holds the configuration. The module holds neither.

Enumeration, once at boot

After reset the head walks slots 0..N and sends an IDENT mailbox request to each. A module that answers returns its type, hardware revision, firmware version, serial number, and its cyclic input and output sizes. From those replies alone the head builds the whole GW_REGION_EXP map — no configuration file is needed to know what is in the rack.

Configuration still matters, but only for things the module cannot know about itself: which AI channel is 4–20 mA and which is 0–10 V, what an input filter time should be, what a safe-state output pattern is. Those are pushed down as SET_PARAM mailbox writes after enumeration, from the same config blob the rest of the gateway already uses.

Check this, it catches real wiring faults

The head puts the slot number it believes it is addressing into every downstream frame, and the module puts the slot number it read from its address pins into every reply. If those two ever disagree, something is wrong that no CRC would catch — a swapped chip select on the backplane, a cracked address resistor, two cards in one slot on a bench harness. Treat a mismatch as GW_Q_CONFIG_ERR and refuse to run that slot.

05 The frame

One shape, both directions, every cycle

SPI is full duplex, so the two frames below are not a request and a response. They are the same 32 clock periods seen from the two ends of the wire. The head shifts its frame out while the module shifts its frame in, simultaneously. Field offsets are deliberately identical in both directions, so there is one parser and one length.

Why the CRC is not enough, and SEQ is

A module whose firmware has hung is the nastiest failure on a bus like this, because its DMA controller does not care. It keeps shifting the last buffer it was given, cycle after cycle, with a perfectly valid CRC. The head sees fresh-looking, correctly checksummed, completely stale inputs — which is exactly the class of bug gw_model.h was written to eliminate on the ESP32 link.

SEQ closes it. The head increments SEQ every cycle. The module copies the SEQ it received into the reply it prepares for the next cycle, so in cycle N the head receives the value it sent in cycle N−1. That relationship is exact and checkable, and it breaks the moment the module stops executing code. Two consecutive cycles with a repeated or wrong SEQ_ECHO is GW_Q_COMM_FAIL, regardless of CRC.

Accept the one-cycle latency, do not fight it

An SPI slave must have its reply already in the transmit buffer before the master starts clocking — there is no time to compute one. So the module answers with the image it prepared at the end of the previous cycle. Inputs the head reads in cycle N were sampled in cycle N−1; outputs it writes in cycle N take effect in cycle N. That is precisely how a PLC process image already behaves, it is deterministic, and every attempt to shave it off ends in a race against the master's clock.

The shared header, in C

/* shared/exp_model.h - compiled by the head AND by every module.
 * Same one-copy rule as shared/gw_model.h: never edit for one side only. */

#define EXP_SOF_DOWN      0xE5u
#define EXP_SOF_UP        0xE6u
#define EXP_HDR_BYTES     8u
#define EXP_MBX_BYTES     6u
#define EXP_CRC_BYTES     2u
#define EXP_CYCLIC_BYTES  16u     /* per-slot; 8 / 16 / 32 / 64 at enumeration */
#define EXP_FRAME_BYTES   (EXP_HDR_BYTES + EXP_CYCLIC_BYTES \
                           + EXP_MBX_BYTES + EXP_CRC_BYTES)   /* 32 */

/* CTRL bits, head -> module */
#define EXP_CTRL_RUN      0x01u   /* drive outputs; clear = go to safe state  */
#define EXP_CTRL_SAFE     0x02u   /* go safe now, a fault exists elsewhere    */
#define EXP_CTRL_LATCH    0x04u   /* apply outputs at end of this frame       */
#define EXP_CTRL_CLRDIAG  0x08u   /* clear latched diagnostics                */

/* STAT bits, module -> head */
#define EXP_ST_READY      0x01u   /* enumerated and parameterised             */
#define EXP_ST_ATTN       0x02u   /* mirrors the ATTN wire                    */
#define EXP_ST_SAFE_ON    0x04u   /* outputs are currently in safe state      */
#define EXP_ST_CFG_ERR    0x08u   /* a parameter was rejected                 */
#define EXP_ST_OUT_FAULT  0x10u   /* short or overload on an output channel   */
#define EXP_ST_IN_FAULT   0x20u   /* broken wire or over-range on an input    */
#define EXP_ST_OVERTEMP   0x40u
#define EXP_ST_FW_BAD     0x80u   /* running a firmware the head refuses      */

/* Every 16-bit field sits on an even offset, so packed costs nothing on
 * either Cortex-M4 and both sides are little endian: no byte swapping. */
typedef struct __attribute__((packed)) {
    uint8_t  sof;                       /* EXP_SOF_DOWN                       */
    uint8_t  slot;                      /* who the head believes this is      */
    uint8_t  ctrl;                      /* EXP_CTRL_*                         */
    uint8_t  seq;                       /* free-running cycle counter         */
    uint8_t  mbxOp;                     /* EXP_MBX_*, 0 = nothing this cycle  */
    uint8_t  mbxLen;
    uint16_t mbxArg;
    uint8_t  out[EXP_CYCLIC_BYTES];     /* cyclic output image                */
    uint8_t  mbxData[EXP_MBX_BYTES];
    uint16_t crc;                       /* crc16() over the first 30 bytes    */
} exp_down_t;

typedef struct __attribute__((packed)) {
    uint8_t  sof;                       /* EXP_SOF_UP                         */
    uint8_t  slot;                      /* read from this module's addr pins  */
    uint8_t  stat;                      /* EXP_ST_*                           */
    uint8_t  seqEcho;                   /* the SEQ seen in the PREVIOUS cycle */
    uint8_t  mbxSt;                     /* GW_ST_*, reused unchanged          */
    uint8_t  mbxLen;
    uint16_t mbxArg;
    uint8_t  in[EXP_CYCLIC_BYTES];      /* cyclic input image                 */
    uint8_t  mbxData[EXP_MBX_BYTES];
    uint16_t crc;
} exp_up_t;

06 Mailbox

Everything rare, in six bytes a cycle

The mailbox is idle in almost every cycle. When it is not, it moves six bytes — which at a 1 ms cycle is 6 kB/s per slot, enough for identity, parameters, diagnostics and even a module firmware image, without ever stealing a byte from the cyclic data or adding a microsecond to the scan.

0x02GET_DIAG—Latched fault word plus the per-channel detail behind whichever EXP_ST_* bit is set. Sent only when ATTN or a status bit asks for it.
0x03SET_PARAMparam indexChannel range (4–20 mA vs 0–10 V), input filter time, counter mode, scaling. Pushed down once after enumeration.

Result codes are the GW_ST_* set already in gw_model.h, unchanged: GW_ST_BAD_CMD for an unknown opcode, GW_ST_RANGE for a parameter index that does not exist, GW_ST_BUSY when the module wants the head to ask again next cycle, GW_ST_NOT_IMPL for anything reserved but not built. Reusing them means the PC tool and the ESP32 already know how to print every error this bus can produce.

07 Process image

The rack is one more region, and nothing above it changes

This is the reason the process-image refactor was worth doing before the expansion bus existed. The ESP32 asks for bytes out of a region; it does not know or care whether those bytes came from an RS-485 slave, a CAN frame or a card three slots down the backplane. Adding a rack therefore touches exactly one layer.

#define GW_REGION_EXP   0x08u   /* expansion rack IO, one sub-map per slot */
#define GW_REGION_COUNT 9u      /* was 8 */
/* additive change -> bump GW_PROTO_VERSION_MINOR, not MAJOR */

A fixed sub-map, like LOCAL_IO — not a configured one

Region 0x02 (Modbus RTU) gets its slot assignment from configuration, because which register lives where is a property of somebody else's device. Region 0x01 (LOCAL_IO) is fixed in the contract, because those slots are wired to pins and a disagreement would close the wrong contactor. Expansion IO is the second kind. Slot 3 channel 6 is a physical terminal on a physical card, so its image address belongs in the header, not in a config blob.

Give each rack slot a fixed stride of 64 image slots. Rack slot s owns image slots s * 64 through s * 64 + 63, whether or not a card is plugged in. Eight rack slots is 512 image slots — 4,608 bytes at the 9-byte value/stamp/quality layout, on a part with 192 KB.

Quality comes out of the bus for free

Every failure this bus can have already has a code in gw_model.h, which is a good sign the abstraction was drawn in the right place:

  • Slot empty, or three consecutive bad CRCs → GW_Q_COMM_FAIL on every channel of that slot.
  • SEQ_ECHO frozen → GW_Q_COMM_FAIL, even though the CRC is fine.
  • EXP_ST_IN_FAULT set → GW_Q_EXCEPTION on the affected channels.
  • Reported slot number ≠ addressed slot number → GW_Q_CONFIG_ERR, and the head stops driving that slot.
  • Analog channel outside its configured limits → GW_Q_OVERRANGE.
  • Module present but not yet parameterised → GW_Q_UNKNOWN until EXP_ST_READY is set.

Writes use the machinery that is already specified: GW_OP_WR_CHANNEL queues a value and returns a token, the exp master folds it into the next downstream frame for that slot, and GW_OP_RD_ACK reports the result one cycle later. No cloud write ever runs inline with a bus transaction — which is the rule the v1 link broke and this whole architecture exists to keep.

08 Head firmware

Which SPI, and the DMA collision waiting on SPI2

ModbusRTU_AWS.ioc already carries SPI2 on PB13/14/15, initialised and unused, and it is the obvious place to put the backplane. Do not. It cannot be given DMA on this part while USART3 also has DMA, and USART3 is the ESP32 link.

Clock and cycle

SPI3 sits on APB1 at 42 MHz, so the prescaler gives 21 MHz at /2 and 10.5 MHz at /4. Start at 10.5 MHz. Signal integrity on an unterminated single-ended backplane, not the peripheral, is what caps this — bring the rack up at 5.25 MHz, prove zero CRC errors over an hour, then step up and watch the error counters. Raising the clock later is a one-line change; a board respin is not.

Drive the cycle from a timer, not from the main loop. A rack scan started by TIM6 at 1 kHz has bounded jitter; one started whenever the main loop comes around inherits every stall in the Modbus scanner. The scan itself is a small state machine that never blocks:

/* exp_master.c - one slot per DMA completion, no blocking anywhere. */

static void exp_start_slot(uint8_t s)
{
    exp_build_down(&g_down[s], s);                 /* image -> frame, + CRC   */
    HAL_GPIO_WritePin(EXP_CS_PORT, exp_cs_pin[s], GPIO_PIN_RESET);
    HAL_SPI_TransmitReceive_DMA(&hspi3,
                                (uint8_t *)&g_down[s],
                                (uint8_t *)&g_up[s],
                                exp_frame_len[s]);
}

/* HAL calls this from the DMA1 Stream2 IRQ when the slot's frame is done. */
void HAL_SPI_TxRxCpltCallback(SPI_HandleTypeDef *hspi)
{
    if (hspi != &hspi3) return;

    HAL_GPIO_WritePin(EXP_CS_PORT, exp_cs_pin[g_slot], GPIO_PIN_SET);
    exp_consume_up(&g_up[g_slot], g_slot);          /* CRC, SEQ, -> image     */

    if (++g_slot < g_slotCount) exp_start_slot(g_slot);
    else                        g_scanBusy = 0;     /* rack refreshed         */
}

/* TIM6 period elapsed, 1 kHz. */
void exp_tick(void)
{
    if (g_scanBusy) { g_overrun++; return; }        /* never stack two scans  */
    g_scanBusy = 1; g_slot = 0; g_seq++;
    exp_start_slot(0);
}

Everything expensive — enumeration, parameter download, diagnostics, firmware chunks — happens by setting mbxOp in one slot's frame and reading the answer next cycle. There is no separate code path, no second transport, and no place where a slow operation can hold the bus.

09 Module firmware

The slave side, and the two things that will bite

Put the module's SPI1 in slave mode on PA4–PA7 (AF5) with DMA2 Stream0 Channel3 for RX and Stream3 Channel3 for TX. The entire module firmware is one interrupt and one background loop.

Use hardware NSS, not software NSS

This is not a style preference; the shared MISO rail depends on it. With hardware NSS management the STM32 slave releases MISO to high impedance whenever NSS is high, so seven unselected modules sit silently on the same wire. With software NSS the pin is driven whenever SPI is enabled, and the second card you plug in fights the first. Confirm it on a scope during bring-up, and if you want the question settled in hardware rather than in an errata, put a 74LVC1G125 on each module's MISO with its output enable tied to that slot's chip select. It costs about four cents and it makes bus contention structurally impossible.

End of frame comes from EXTI on NSS, not from the byte count

A slave cannot tell “frame complete” from “frame aborted after 19 bytes” by watching DMA alone. Configure EXTI4 on PA4 for the rising edge — EXTI samples the pin regardless of it being in alternate-function mode — and treat that edge as the frame boundary. In that handler, read NDTR: if the remaining count is not zero, the transaction was truncated by noise or a hot-plug, so discard it, clear the SPI overrun flag by reading DR then SR, and re-arm. Silence is always safer than a half-parsed output image.

/* exp_slave.c - the whole module data path. */

void EXTI4_IRQHandler(void)              /* NSS rising edge = frame boundary */
{
    __HAL_GPIO_EXTI_CLEAR_IT(EXP_NSS_PIN);

    uint16_t left = __HAL_DMA_GET_COUNTER(hspi1.hdmarx);
    HAL_SPI_DMAStop(&hspi1);

    if (left == 0 && exp_frame_ok(&g_rx)) {      /* SOF, slot, CRC          */
        g_lastGoodMs = HAL_GetTick();
        exp_apply_outputs(&g_rx);                /* drive terminals now     */
        exp_service_mailbox(&g_rx, &g_tx);       /* may take a few hundred us */
    } else {
        g_crcErrors++;
    }

    exp_sample_inputs(&g_tx);                    /* for the NEXT cycle      */
    g_tx.seqEcho = g_rx.seq;                     /* liveness proof          */
    exp_seal(&g_tx);                             /* CRC over 0..29          */

    HAL_SPI_TransmitReceive_DMA(&hspi1, (uint8_t *)&g_tx,
                                (uint8_t *)&g_rx, EXP_FRAME_BYTES);
}

/* Background loop. The head cannot save a module that has lost the head. */
void exp_slave_poll(void)
{
    if (HAL_GetTick() - g_lastGoodMs > EXP_SAFE_TIMEOUT_MS) {   /* 100 ms */
        exp_drive_safe_state();
        g_tx.stat |= EXP_ST_SAFE_ON;
    }
}

Safe state belongs to the module

Give every module a configurable safe-state output pattern, pushed down once with SET_SAFE and stored in its flash. If the module stops receiving valid frames for EXP_SAFE_TIMEOUT_MS, it drives that pattern on its own initiative and sets EXP_ST_SAFE_ON so the head learns about it the moment the bus recovers. Back it with the independent watchdog, which is the one thing that still works when the application has hung.

Default the timeout to about 100 cycles. Too short and a single burst of electrical noise trips a plant; too long and a cut backplane leaves a valve open. There is no universal right answer, which is why it is a parameter and not a constant.

One firmware, many module types

Build a single binary for every card and let it discover what it is: four more strapping pins on the module PCB, or a resistor divider into ADC1, read once at boot. The module type selects the IO driver table and the cyclic length it reports in IDENT. One build, one flash image, one thing to version — and the head learns the rack contents from the bus rather than from a spreadsheet.

On the F407VG choice

An F407VG for a card that reads sixteen contacts is roughly ten times the microcontroller the job needs, and at volume the difference against an STM32G0B1 or G431 is several dollars a card. It is still a defensible decision for the first generation, and for a reason worth naming: one part number, one HAL, one toolchain, one debug setup, one firmware base shared with the head. That is real engineering time saved and real inventory risk avoided. Just make it a decision rather than a default — keep the module firmware free of F4-only assumptions (no FPU maths in the IO path, no assumption of 192 KB of RAM), and the day the analog card needs a cheaper BOM, the port is a week rather than a rewrite. Nothing in this protocol requires a Cortex-M4 at either end.

11 Electrical

The rules that decide whether 10 MHz works

SPI is chosen here precisely because the distance is short and controlled. That advantage is only real if the backplane is designed to keep it.

  • Source-terminate SCK and MOSI at the head, 22–33 Ω in series, one resistor each, placed at the driver. On an unterminated multi-drop bus this is what damps the reflections that otherwise show up as CRC errors at exactly the clock rate you wanted to use.
  • Daisy-chain the clock, do not star it. One trace that visits each slot in order, with the shortest possible stub into each connector. A star topology on SCK is the single most common reason a backplane tops out at 2 MHz.
  • Interleave grounds in the connector — several ground pins spread across the row, not one at the end. The return current for SCK has to have somewhere short to go.
  • 10 kΩ pull-down on MISO at the head, so an empty rack reads a defined constant rather than picking up whatever is nearby.
  • Keep the backplane inside one isolation domain. Isolate at the field terminals, per channel or per group, using the module's own optocouplers or digital isolators. Do not try to isolate the backplane itself: eight isolated SPI channels is expensive, slow, and solves a problem you do not have inside a single enclosure with one ground.
  • ESD protection on the connector for every signal that leaves a board, even inside the enclosure — a card gets handled by a person before it gets plugged in.

Hot swap, honestly

The protocol tolerates a card appearing and disappearing: that is what the CRC, the enumeration step and GW_Q_COMM_FAIL are for. The electronics are a separate question, and the honest v1 answer is to design the connector for hot swap and not promise it yet:

  • Stagger the pin lengths — ground longest, then power, signals shortest. Ground makes first and breaks last, always.
  • Limit inrush into the module's bulk capacitance, with an NTC or a soft-start FET, so plugging a card does not brown out the rack.
  • The series resistors on SCK and MOSI already limit the current a hot-plugging card can inject into a driver pin.
  • Then test it a thousand times before it goes in a datasheet. Hot swap is a claim that gets audited in the field, by an electrician, at the worst possible moment.
12 Order of work

Seven steps, each one testable on its own

The ordering rule is the same one that shaped link v2: never build the board before the protocol runs on a bench wire, and never add a second module until one is boring.

1
Two boards, one wire, ECHO only
A Nucleo or your existing head board plus one F407VG on flying leads, 100 mm maximum. Fixed 32-byte frame, MBX_ECHO, nothing else. Run it for an hour at 5.25 MHz and log CRC errors. 13 Decisions

Eight answers needed, one of them urgent

Only the first can change the protocol. The rest change sizes, pin counts and schedule.

1  ·  Are the modules always in the same rack as the head?

This is the only question here that decides SPI versus CAN, and everything downstream of it is wasted work if it is answered late. Same rack, backplane connector, under 300 mm total: SPI, as described. Separate enclosure, cable, or any distance you would describe in metres: CAN at 1 Mbit/s with the same frame contents split across multiple IDs, accepting a 2–5 ms cycle.

Recommendation Answer “same rack” and build SPI. If remote I/O is also a product requirement, serve it over the RS-485 port you already have — as a Modbus field device, not as an expansion module. Two mechanisms, each honest about what it is, beats one that is bad at both.

2  ·  How many slots, maximum?

Eight fits on PE0..PE7 with no decoder and no pin pressure. Sixteen needs either a 4-to-16 decoder on the head or eight more GPIOs, both cheap, but it doubles the backplane length and so cuts the maximum clock.

Recommendation Eight slots, four address bits. The address field already reaches sixteen, so a second rack generation costs no protocol change.

3  ·  What cycle time are you selling?

The bus does 290 µs for eight slots, so 1 ms is comfortable, 500 µs is reachable, and 10 ms would waste the design. But the number that matters is not the bus — it is the total loop through the Modbus scanner and the application logic.

Recommendation Specify 1 ms for the rack and publish the real measured jitter. A PLC that honestly states 1 ms ±50 µs is worth more than one that claims 200 µs and occasionally takes 4 ms.

4  ·  Is hot swap under power a product requirement?

It changes the connector, the inrush design and roughly a month of testing. The protocol already supports it either way.

Recommendation Design the connector for it now — staggered pins cost nothing at layout time and cannot be retrofitted — and document v1 as power-down insertion. Promote the claim after the thousand-cycle test, not before.

5  ·  Which module types ship first?

Each type is an IO driver table plus an entry in the type list, but the analog ones also drag in calibration, storage for calibration constants, and a production test fixture.

Recommendation 16 DI and 16 relay DO first, because they prove the bus without the calibration problem. 8 AI third. High-speed counters last — they are the one card that may genuinely want a faster cyclic rate than the rest of the rack.

6  ·  Fixed 16-byte cyclic data for every card, or per-type sizes?

Fixed is simpler: one constant, one DMA length, one buffer. Per-type saves bus time on small cards and allows a 32-channel analog card later without a protocol change.

Recommendation Put the size in IDENT from day one and hard-code 16 bytes for the first two card types. The field exists, costs nothing, and cannot be added later without breaking every deployed rack.

7  ·  Does SPI2 stay in the .ioc?

It is initialised, unused, and its pins (PB13/14/15) collide with RMII_TXD1 if native Ethernet ever lands.

Recommendation Remove SPI2 from the .ioc when you add SPI3. Regeneration rewrites main.c either way, so the cost is one CubeMX pass, and it frees the pins for Ethernet while leaving MX_SPI3_Init as the only SPI in the project.

8  ·  Module firmware update over the bus, or SWD per card?

SWD is free and needs a technician with a probe and the enclosure open. Over-the-bus needs a bootloader, two flash slots per module, and a rollback story.

Recommendation SWD for v1, but reserve 0x10–0x12 in the mailbox and lay out the module's flash as two slots from the first board. Reserving is nearly free; repartitioning a deployed fleet is not.
